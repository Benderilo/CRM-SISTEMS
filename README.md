# CRM SISTEMS — CRM, сайт магазина и бот MAX для любого магазина

Универсальная версия CRM: одно приложение ведёт сколько угодно магазинов,
и для каждого само ставит сервер на ваш VPS.

* **Android-приложение** — учёт товаров, клиентов, продаж, расходов и аналитика.
  База лежит на телефоне (SQLite/Room), без интернета всё работает.
  Магазинов может быть несколько: у каждого своя база и настройки
  (бургер-меню → «Мои магазины»).
* **Сайт магазина** (`server/`) — витрина с корзиной, приём заказов, панель
  управления и REST API для приложения. Один Go-бинарь и одна база SQLite.
  Название, тексты, контакты — правятся из приложения, в коде ничего не зашито.
* **Бот MAX** — каталог и приём заказов в мессенджере, живёт внутри сервера.
  Токен бота и ключ ИИ вписываются в приложении.

## Как запустить новый магазин

1. Купить VPS с Ubuntu 22.04/24.04 (1 ядро, 1 ГБ), по желанию — домен с
   A-записью на IP сервера.
2. В приложении: «Мои магазины» → «Добавить магазин» → «Открыть и настроить».
3. Вписать IP, пароль сервера, название магазина и домен → «Установить».
   Приложение по SSH зальёт сервер (он лежит внутри APK), поставит nginx,
   HTTPS, службу, файрвол и ночные копии, а адрес и ключ запишет себе само.
4. «Контакты» — тексты сайта; «Бот MAX» — токен бота и ключ ИИ.

У каждого поля в настройках есть «?» с объяснением, что вписывать и где это взять.

| Документ | О чём |
|---|---|
| [server/SETUP.md](server/SETUP.md) | что делает установка, установка и обновление с компьютера, переезд |
| [server/README.md](server/README.md) | устройство сайта, панель управления, REST API |
| этот файл | приложение: экраны, обмен с сайтом, сборка |

### Обмен с сайтом

Синхронизация идёт по одному обмену на всё приложение (`net/SyncManager.java`):
сначала уходят накопленные офлайн-правки, затем новые товары и клиенты, потом
продажи, и только после этого забираются заказы и свежие списки. Главным
считается сайт — он видит покупки и списывает остатки.

Что важно знать:

* заказы живут на сервере, в телефоне лежит только их кэш для просмотра офлайн;
* продажа из приложения — это заказ на сайте с пометкой «app»;
* заказы с одного телефона объединяются в один, пока он в работе: сайт делает
  это при оформлении, а старые дубли приложение сводит при обмене
  (`/api/v1/crm/orders/merge`) — в списке одна карточка на покупателя;
* сообщение с телефоном, написанное боту MAX или в группу, превращается в
  заявку: клиент заводится по номеру, само сообщение ложится в комментарий
  заказа — там же в приложении его и правят;
* запись, которую сайт не принял (пустое название, городской телефон),
  пропускается, а в сводке пишется, сколько не ушло;
* удалённый заказ пропадает из приложения, но остаётся в базе телефона: в
  выгрузке в Excel видна вся история, включая стёртые выполненные заказы —
  за этим в файл и заходят;
* офлайн-правки статусов копятся в очереди и уходят, когда появляется сеть.

### Сборка на неделю

Список товаров с общим количеством по подтверждённым заказам текущей недели —
по нему собирают развозку. Неделя идёт с понедельника по воскресенье и
начинается заново каждый понедельник. Заказ попадает в сборку после статуса
«Принят» и уходит из неё, когда становится «Выполнен».

### Обмен данными (Настройки → «База данных»)

* **Выгрузить в Excel** — вся база одной книгой: товары, клиенты, заказы,
  расходы и отдельный лист «Состав заказов» (по строке на позицию).
* **Загрузить из Excel** — та же книга обратно: строки с тем же ID обновляются,
  новые добавляются, ничего не удаляется. Перед загрузкой приложение само
  кладёт резервную копию в «Загрузки». Лист «Заказы» только для просмотра —
  заказами управляет сайт.
* **Другие форматы** — CSV по таблицам и полная копия в JSON.
* **Очистить заказы** — удалить на сайте выполненные или все заказы; сервер
  перед удалением сохраняет их в файл рядом с базой.
* **Очистить базу** — стереть всё в телефоне, с двойным подтверждением и
  автоматической резервной копией.

## Сборка приложения

```sh
./gradlew :app:assembleDebug          # отладочная сборка
./gradlew :app:assembleRelease        # релизная (нужен свой ключ подписи)
```

APK появится в `app/build/outputs/apk/`. Перед сборкой Gradle сам собирает
Go-сервер под Linux (amd64 и arm64) и кладёт его в APK (задача
`buildShopServer`), поэтому на компьютере нужен Go 1.21+ в PATH. Java 17, minSdk 26, Views + Room,
без внешних библиотек для сети и картинок.

Тесты сервера:

```sh
cd server && go test ./...
```

## Устройство репозитория

```
app/                 Android-приложение (Java, Views, Room)
server/              сайт магазина и бот MAX (Go, SQLite, html/template)
  maxbot*.go         бот MAX: транспорт, диалог, настройки, разбор обращений,
                     перехват сообщений с телефоном
  site.go            тексты витрины и новости, правятся из приложения
  photos.go          уборка фотографий, на которые не ссылается ни один товар
  templates/         страницы витрины и панели управления
  SETUP.md           установка на сервер
```

Ключи и пароли в репозиторий не кладутся: `SHOP_API_KEY` живёт в
`crmshop.env` на сервере и приходит в приложение при установке, токен бота
и ключ ИИ — в базе сервера. Пароли подписи APK — в `local.properties`
(`keystore.file`, `keystore.password`, `keystore.alias`, `keystore.keyPassword`).
