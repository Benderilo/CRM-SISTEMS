# Установка магазина на Ubuntu

Обычно ничего из этого делать руками не нужно: в приложении бургер-меню →
**«Установка на сервер»**, вписать IP и пароль VPS — приложение само зальёт
сервер и выполнит `install.sh`. Этот файл — для тех, кто хочет понимать, что
происходит, или поставить магазин с компьютера.

Рассчитано на Ubuntu 22.04 / 24.04 и Debian 12, процессоры x86_64 и ARM64.

## Что нужно

* VPS с Ubuntu и публичным IP (хватит 1 ядра и 1 ГБ памяти);
* по желанию — домен с A-записью на IP сервера (тогда будет HTTPS);
* пароль root (или пользователя с sudo).

## Что делает install.sh

1. Ставит пакеты: `nginx certbot python3-certbot-nginx sqlite3 ufw curl openssl`.
2. Заводит системного пользователя `crmshop` и папку магазина `/opt/crm/ИМЯ/`.
3. Кладёт бинарь `crmshop`, пишет `crmshop.env` (ключ API генерируется один раз
   и при переустановке сохраняется), выбирает свободный внутренний порт от 8100.
4. Создаёт службу `crm-ИМЯ` (systemd) и запускает её.
5. Пишет конфиг nginx `/etc/nginx/sites-available/crm-ИМЯ`.
6. Открывает в ufw порт SSH и 80/443, включает файрвол.
7. С доменом — получает сертификат Let’s Encrypt и включает HTTPS.
8. Ставит ночную резервную копию (`/etc/cron.d/crm-ИМЯ-backup`, 4:00).

| Путь | Что там |
|---|---|
| `/opt/crm/ИМЯ/crmshop` | сервер магазина (один файл) |
| `/opt/crm/ИМЯ/crmshop.env` | порт, пути, ключ API — права 640 |
| `/opt/crm/ИМЯ/data/shop.db` | база: товары, клиенты, заказы, тексты сайта, бот, ключ ИИ |
| `/opt/crm/ИМЯ/data/uploads/` | фотографии товаров |
| `/var/backups/crm-ИМЯ/` | резервные копии, 14 последних |

На одном сервере можно держать несколько магазинов с разными `ИМЯ` (SLUG) и
доменами — каждый получает свою службу, порт и папку.

## Установка с компьютера

```sh
cd server
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o crmshop .
ssh root@IP 'mkdir -p /tmp/crmshop-upload'
scp crmshop install.sh backup.sh root@IP:/tmp/crmshop-upload/
ssh root@IP 'SLUG=shop DOMAIN=shop.example.ru EMAIL=me@example.ru ADMIN_PASS=пароль bash /tmp/crmshop-upload/install.sh'
```

В конце скрипт печатает строки `@@RESULT url=…` и `@@RESULT key=…` — адрес
сайта и ключ для приложения («Сайт магазина» → адрес и ключ доступа).

Без `DOMAIN` сайт будет на `http://IP` без HTTPS. Бесплатный домен без
покупки: `DOMAIN=185-12-34-56.sslip.io` (IP через дефисы).

## Обновление

Из приложения — кнопка «Обновить сервер» на том же экране. С компьютера:

```sh
sh server/deploy.sh root@IP shop
```

Перед заменой снимается резервная копия; прежний бинарь остаётся рядом как
`crmshop.bak-ДАТА` (три последних). База при обновлении не трогается: новые
таблицы и столбцы сервис добавляет сам.

Откат:

```sh
ssh root@IP 'cd /opt/crm/shop && cp -a "$(ls -1 crmshop.bak* | sort | tail -1)" crmshop && systemctl restart crm-shop'
```

## Бот MAX и ИИ

Настраиваются из приложения, на сервере ничего делать не нужно:

* **Бот MAX** → вставить токен от `@MasterBot` → «Проверить связь» →
  включить → «Сохранить». Добавить бота в группу и сделать администратором.
* Там же **ключ ИИ** (ollama.com → Settings → Keys). Ключ хранится в базе
  на сервере и в приложение обратно не отдаётся. Можно и прописать его в
  `crmshop.env` строкой `SHOP_AI_KEY=…` — ключ из приложения важнее.

## Переезд на другой сервер

Установите магазин на новый сервер с тем же `SLUG`, затем перенесите данные:

```sh
# на старом
systemctl stop crm-shop                 # чтобы SQLite дописал журнал в файл базы
tar czf /root/shop-data.tar.gz -C /opt/crm/shop data
scp /root/shop-data.tar.gz root@НОВЫЙ_IP:/root/

# на новом
systemctl stop crm-shop
tar xzf /root/shop-data.tar.gz -C /opt/crm/shop && chown -R crmshop:crmshop /opt/crm/shop/data
systemctl start crm-shop
```

Ключ API на новом сервере другой — приложение получит его само при установке.
Ключ ИИ и токен бота переезжают вместе с базой.

## Если что-то не работает

```sh
systemctl status crm-shop --no-pager
journalctl -u crm-shop -n 50 --no-pager
nginx -t
cat /opt/crm/shop/install.conf     # порт и адрес сайта
```

| Симптом | Что делать |
|---|---|
| «Сервер не принял логин или пароль» | у части VPS root по паролю выключен — войдите пользователем с sudo |
| «Сервер предъявил другой ключ» | сервер переустанавливали — «Забыть ключ сервера»; иначе не продолжайте |
| Сертификат не выдан | домен ещё не указывает на IP — проверьте A-запись и запустите установку снова |
| Приложение пишет «Неверный ключ» | ключ в приложении и `SHOP_API_KEY` в `crmshop.env` разошлись |
| Бот не отвечает в группе | у бота нет прав администратора в этой группе |
